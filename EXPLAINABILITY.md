# OmniSight - Explainability

## What This System Does

OmniSight is an enterprise risk intelligence platform that orchestrates multiple AI agents to synthesize risk data from client health, workforce dynamics, financial projections, and weak signals into unified, actionable intelligence for decision-makers.

## How It Works

### Agent Architecture

OmniSight uses a manager-subagent pattern where the **Executive Orchestrator** coordinates seven specialized agents:

| Agent | Role | Input | Output |
|---|---|---|---|
| Data Harmonization | Normalizes raw data from multiple sources | Raw multi-source data | Harmonized, standardized datasets |
| Client Intelligence | Assesses churn risk and account health | Client engagement data | Churn risk scores, health indicators |
| Workforce Dynamics | Evaluates team stability and resource allocation | Workforce metrics | Stability scores, resource reports |
| Financial Forecasting | Projects revenue with confidence intervals | Financial data | Best/expected/worst-case projections |
| Weak Signal Detection | Identifies pre-risk indicators early | Cross-domain signals | Early warning alerts with severity |
| Action Simulation | Compares intervention scenarios | Risk context, proposed actions | No-action vs recommended vs auto-execution outcomes |
| Intervention Feedback | Analyzes historical action outcomes | Past intervention logs | Recalibrated impact scores, feedback reports |

### Decision Flow

1. **Data Ingestion**: Data Harmonization normalizes inputs from multiple enterprise sources.
2. **Domain Analysis**: Client Intelligence, Workforce Dynamics, and Financial Forecasting analyze their respective domains in parallel.
3. **Signal Detection**: Weak Signal Detection scans for early-warning indicators across all domains.
4. **Synthesis**: The Executive Orchestrator merges all sub-agent outputs into a unified risk score with confidence intervals and data coverage metadata.
5. **Simulation**: Action Simulation models three scenarios (no-action, recommended intervention, auto-execution) before any recommendation is made.
6. **Feedback Loop**: Intervention Feedback continuously evaluates past actions to recalibrate future predictions.

## How Outputs Are Generated

### Risk Scores
- Each risk score includes a **confidence interval** (e.g., 0.72 +/- 0.08) and **data coverage percentage** indicating how much of the relevant data was available.
- Scores are composites derived from weighted sub-agent assessments across client, workforce, and financial domains.

### Pre-Risk Alerts
- Generated by the Weak Signal Detection agent when early indicators cross defined thresholds.
- Each alert includes the signal source, severity level, and recommended monitoring actions.

### Financial Projections
- The Financial Forecasting agent produces three scenarios (best, expected, worst) with explicit confidence intervals.
- Projections are grounded in historical trends and current data, not speculative modeling.

### Action Recommendations
- Every recommendation is preceded by simulation of at least three scenarios.
- The system presents comparative outcomes so decision-makers can evaluate trade-offs before acting.

### Feedback Reports
- The Intervention Feedback agent tracks the actual outcomes of past interventions.
- Impact scores are recalibrated based on measured results, creating a continuous improvement loop.

## Limitations and Boundaries

- **Data dependency**: Output quality is directly tied to input data quality and completeness. The system discloses when data is insufficient or stale.
- **Not autonomous**: OmniSight provides intelligence and simulations but does not execute business decisions without explicit user authorization.
- **Confidence transparency**: All outputs include confidence levels. Low-confidence outputs are flagged rather than presented as definitive.
- **Historical bias**: Feedback recalibration relies on historical outcomes, which may not fully predict novel scenarios.
- **No real-time streaming**: Analysis is performed on data snapshots, not continuous real-time feeds.

## Data Handling

- All data is processed within the platform's provisioned database (`app_d35edbe23760fcbc1d91f5a0`).
- User data is scoped per user via row-level security — users only see their own risk data, alerts, and reports.
- No data is shared across user accounts or exported to external services without explicit action.

## Model Information

- Agents are powered by large language models via the Lyzr platform.
- Each agent has a defined role, goal, and instruction set that constrains its behavior to its specific domain.
- Temperature and model parameters are tuned per agent for the appropriate balance of creativity and precision (lower for financial forecasting, moderate for signal detection).

## How to Interpret Results

- **High confidence (>0.8)**: Strong data support; actionable with reasonable certainty.
- **Medium confidence (0.5-0.8)**: Sufficient for awareness and monitoring; verify before major decisions.
- **Low confidence (<0.5)**: Flagged as uncertain; treat as directional signals, not definitive assessments.
- **Simulation comparisons**: Always review all three scenarios before selecting an intervention path.
- **Feedback scores**: Higher recalibrated impact scores indicate interventions with stronger historical track records.
